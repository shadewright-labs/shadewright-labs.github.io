# shadewright-labs.github.io

The organisation site of Shadewright Labs: one page about the house, its products (Shadewright, Sablecourt and Nightloom) and the security laws they share. It is plain HTML and CSS with no build step, no JavaScript and no requests to other sites.

The site will be served at https://shadewrightlabs.com once the custom domain is set up. Until then it is at https://shadewright-labs.github.io. All links inside the site are relative or start at the site root, so it works on both hosts.

## Layout

| Path | Contents |
| --- | --- |
| `index.html` | The landing page |
| `404.html` | The page GitHub Pages serves for a missing path. Its links start at `/` because it is served at any depth. |
| `assets/site.css` | The only stylesheet |
| `assets/products-diagram-*.svg` | The diagram of how the products fit together: a wide version, and a tall one for narrow screens. Generated by `scripts/gen-diagram.py` (`python3 -I scripts/gen-diagram.py assets`); change the script, not the SVG. |
| `assets/<identity>/` | The house lockups, favicons and social preview image, and each product's logo (AVIF at 1x and 2x, JPEG fallback), from the Shadewright Labs brand kit |
| `robots.txt`, `.nojekyll` | Crawl rules, and a marker that turns off Jekyll processing on Pages |
| `.well-known/security.txt` | Where to report a security problem ([RFC 9116](https://www.rfc-editor.org/rfc/rfc9116)). Renew its `Expires` date before it passes. |
| `scripts/stage-site.sh` | Copies the published files from an allow-list into a staging folder and fails on anything else |
| `scripts/check-pages.py` | Fails if a page loads anything from another origin, has inline code or styles, or lacks the Content-Security-Policy |
| `package.json`, `package-lock.json`, `.htmlvalidate.json` | The pinned HTML validator used by CI. Not published. |

## Paths and repositories

GitHub Pages serves this repository at the root of the domain. Each project repository of the organisation that turns on Pages is served under a path named after the repository, from that repository's own Pages build.

| URL path | Published from |
| --- | --- |
| `/` | This repository |
| `/sablecourt/` | The [Sablecourt repository](https://github.com/shadewright-labs/sablecourt)'s own Pages build (not published yet; until it is, the page links to the docs folder on GitHub) |

Do not add a `sablecourt/` directory here: the path belongs to the Sablecourt repository, and a directory of the same name here would conflict with it. Shadewright's documentation has its own domain, https://shadewright.io/, and is not served under this site.

## Preview locally

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000/. The local server does not serve `404.html` for missing paths the way Pages does; open http://localhost:8000/404.html to see it.

## Checks

Pull requests run `.github/workflows/ci.yml`. The required check is `ci-ok`, which passes when these jobs pass:

- HTML validation with [html-validate](https://html-validate.org/), pinned in `package-lock.json`. Locally: `npm ci --ignore-scripts && npm run validate`.
- Links with [lychee](https://lychee.cli.rs/), downloaded at a pinned version and checked against its SHA-256. Every internal link, asset and anchor must resolve. External links fail the job on an error such as a 404, but not on a timeout or a rate limit.
- The page policy: `scripts/stage-site.sh` and `scripts/check-pages.py` on the staged site. Every page carries a Content-Security-Policy in a `<meta>` element (Pages cannot send headers) that allows only the site's own images and stylesheet, so a page must not load anything from another origin or carry a `<script>`, a `<style>` element or a `style=` attribute.
- [actionlint](https://github.com/rhysd/actionlint) and [zizmor](https://github.com/zizmorcore/zizmor) on the workflows and the Dependabot configuration, each downloaded at a pinned version and checked against its SHA-256.

Dependabot proposes updates to the pinned actions and to the npm packages once a week, grouped, after a 7-day cooldown.

## Publishing

`.github/workflows/pages.yml` runs on every push to `main`. `scripts/stage-site.sh` copies the site files (`index.html`, `404.html`, `robots.txt`, `.nojekyll`, `assets/` and `.well-known/`) into a staging folder, the page policy is checked again, and the folder is deployed with the official Pages actions, pinned to commit SHAs. Nothing else in the repository is published. The upload includes hidden files, because `.well-known/` would otherwise be left out; the staging script allows no dotfiles besides `.nojekyll` and `.well-known/`.

The repository's Pages settings must use "GitHub Actions" as the source. There is no `CNAME` file yet: the custom domain is set in the repository settings when DNS for shadewrightlabs.com points at GitHub Pages.
